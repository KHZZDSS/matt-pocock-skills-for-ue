# UE 工作流适配基准

状态：2026-10-07 建立的设计与评估基准。当前技能尚未按本基准改造；逐技能状态见 [upstream.json](../upstream.json)。安装单个上游 skill 不会自动获得本文件的行为。

来源：2026-10-06 对“受击累计计时与行为树恢复连招”任务从探讨、拆分到实施的会话复盘，以及用户对单编辑器、单 PIE 环境的说明。以下原则针对这种资源配置；其他项目先读取实际能力，不能将它写成 UE 引擎的普遍限制。

## 目标

保留规格驱动、完整行为切片、公开接口验证、独立审查和明确收尾。适配资源调度、隔离方式、验证粒度及审查时机。优化整个任务取得可信结果的成本，同时保留必要审批和运行时证据。

衡量总耗时、编辑器重启与冷构建次数、资源等待、重复查找、夹具失败占比及审查后的生产缺陷。并发代理数、工具调用数和测试数量本身不代表效率。

## P1：按资源调度并行工作

独立源码实现、只读分析和审查可并行；同一编辑器中的资产写入与 PIE 由一个执行者串行处理。先确认构建是否共享锁、产物或机器资源，再安排并发。

工单同时说明功能依赖、共享接口、文件或资产归属及验证资源。调度器按稳定提交组织构建和 PIE 批次，减少逐条申请资源的往返。角色数量由实际职责决定，不将每个步骤都变成独立交接。

## P2：隔离源码，复用重型验证环境

worktree 按冲突隔离需要创建；每票建立完整可运行 UE 副本不是默认要求。可保留一个稳定的集成验证工作区，复用依赖和缓存，由唯一执行者控制版本切换。

实现前冻结必要源码、配置、自建资产及其依赖，明确未提交内容是否纳入；首次准备环境先检查关键资产加载。共享目录方案须验证初始化、合并与归档，不能让 Git 路径清理穿透到共享资源。

验证记录源码提交或明确差异、资产清单、构建来源及实际加载的工程/模块。版本切换遵守项目的保存、关闭和重载规则。旧缓存可以复用，旧结果必须重新判断适用性。

## P3：按反馈成本分层验证

| 对象 | 默认方式 | 完成证据 |
| --- | --- | --- |
| 低成本、有独立输入输出的逻辑 | 小步 red-green | 正确原因的行为失败与修复后通过 |
| UE 原生集成、资产结构与保存 | 首次接入验证代表路径，接口稳定后按行为组批量验证 | 实际报告、资产读回；新写入方式须验证重载 |
| 可见 PIE、真实动画与完整交互 | 已验证夹具上的有界批次，一次编译/启动收集整组结果 | 实际运行报告及需要的可见证据 |

按实际启动与执行成本分类，不能仅因测试叫 native 就认定便宜。配置、简单接线或没有独立断言依据的改动采用相称检查，不为仪式编写重复实现的测试。

保留逐场景结果和来源。共享接口变化、阻塞下游或高风险失败时及时验证；场景组稳定、等待已无收益时执行批次，不无限积攒到末尾。批量验收不要求先猜测并写完所有未知机制的测试。

## P4：先验证夹具能正确刺激和观察系统

第一条代表用例确认 PIE 启停、对象位置、实际枚举、事件入口及取消/销毁后的观察者清理。准备条件失败、编译失败、夹具崩溃与生产行为失败分开报告。

动画点位和预期资产从当前状态读取；时间断言留出可观察区间。窗口归属以权威查询为准，不强制非契约的通知顺序。新资产写入方式先验证保存、重载和独立读回，再扩展接线。

将已验证的夹具、环境恢复和报告汇总固化为项目工具。修正失效的假设，不修改生产行为去迎合错误夹具。

## P5：在昂贵最终验收前暴露生产问题

生产实现汇合后冻结审查版本，独立审查与最终验收准备可并行。确认的生产修复集中合入，再运行最终昂贵批次；审查后新增差异仍需相应审查和回归。

问题按责任回流：需求或行为决策回到设计，执行或夹具问题回到对应实现者。局部修正不自动重启全部角色，独立审查不替代用户对高风险动作的授权。

## P6：提前推进与完成验收分开表达

“接口稳定，可以开始依赖工作”“已集成，等待验证”“验收通过”是不同事实。下游可基于固定接口准备代码；依赖实际资产、运行结果或未决行为的部分等待相应证据。

未验证的合并不能关闭工单或宣称完成。既有结果在源码、资产、环境及断言前提未受影响时可复用，须标出原验证版本；不能写成当前版本新执行的结果。

## P7：事实先于设计约束

区分现有行为、用户决定与代理方案。迁移前查原参数、生命周期和入口；实现建议是待验证选择，避免让用户重复澄清已有机制。

历史资料用于导航，当前声明、schema 和实读用于执行。重复的 schema 解包、名称检索和平台路径错误适合工具修正。缓存绑定编辑器身份和 schema 版本，变化后刷新。

## P8：维护小范围且可追溯的差异

每次 skill 改动记录上游路径、精确基线提交、状态、理由和实际验证。原样保留不代表 UE 适用；适配完成也不代表已经实战验证。

保持原授权内的自主完成。缺失产品决策、明确审批边界或扩大范围才需要用户介入；已确认接口和权限随当前任务持续有效。规则须对应真实决策差异，不将单次故障扩展成普遍审批或无止境检查。

上游升级按 [同步约定](upstream-sync.md) 评估；上游解决同一问题时删除多余本地差异。

## 本次复盘依据

这些是特定任务的观察，不是时间承诺，也不能相加为可节省总时长。

| 观察 | 改进依据 |

| 最终 64 项原生测试约 6.9 秒、5 项可见集成约 11.1 秒，外围却反复编译、重启和交接 | 包含启动成本组织批次（P1、P3） |

| 工作树基线后补 37 个自建资产；共享副本因稀疏检出清理而恢复 744 个文件 | 依赖和共享目录生命周期检查（P2） |
| 原生 ASC 子对象配置内存读回成功，重启后未保存 | 首次写入方式验证重载（P4） |
| 最终验收通过后才发现 BT 审查问题，再建工作区、编译和回归 | 审查前移并绑定版本（P5） |

没有充分证据将该任务归因于过时文档；参数旧记录被实时复核。旧 Task 影响新播放、同步重入产生重复位移有实际失败支撑，不能把身份和生命周期检查概括为过度防御。

不复制私人会话全文、项目资产或机器路径。以上摘要是维护依据，尚未运行新工作流的效果对照。

## 首批适配候选

候选不代表已实施，实际状态以清单为准。

| 候选 | 需要验证的决策变化 |
| --- | --- |
| `implement-spec` / `implement` | 源码并行、单编辑器调度、按需 worktree、版本锚点、提前审查、未验收不关单 |
| `to-tickets` | 完整行为切片与资源约束同时表达，依赖解锁不等于整项验收完成 |
| `tdd` 或独立 UE 验证 skill | 按成本选择小步验证或批次，先验证夹具，保留独立断言 |
| `ask-matt` | 执行技能适配后同步路由，不重新导回原版编排 |

代表场景：纯 C++ 局部修改、资产属性接线、C++ 与资产混合变更。先无副作用地评估代理调度和完成判断，再在相应任务授权下选择真实 UE 试验；技能维护当次不自动启动 UE。
